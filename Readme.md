# StubsGenerator

## 1. Overview

StubsGenerator is a command-line utility designed to automate the generation of function stubs based on `undefined_reference` error. It simplifies the process of unit testing, making it easier for developers to maintain large projects. 
The tool supports additional options for container usage, integration with CMake-generated Makefiles, and configurable logging outputs.

## 2. Build procedure
Target executable file is `StubsGenerator.exe` located in `build/bin` directory <br>
The build will be created automatically <br>
### 2.1. Prerequisites
- g++ compiler installed on system (Recommended to have MinGW installed on Windows).

### 2.2. In order to build the program into executable file follow these steps:
1. Step into StubsGenerator directory (The `Makefile` should be located here).
2. Invoke `make [release \ debug]` or `MinGW32-make [release \ debug]` for `Windows`. 
The executable file `StubsGenerator.exe` should be generated in `build/bin` directory.

### 2.3. Cleaning the output files:
In order to clean output files use `make clean` or `MinGW32-make clean` for `Windows`.

## 3. Usage
### Usage

```sh
StubsGenerator [path to makefile] [options]
```

- **path to makefile**: The path to the Makefile.

#### Optional parameters:
- `--use_container`  
    Add this flag if a container should be used. \
    The program will ask for any required data, such as container image and container name.

- `--from_cmake`  
    Use this flag if the Makefile was generated from `CMakeLists.txt`. \
    **Important:**  
    The `compile_commands.json` file should exist either in the same directory as the Makefile or in one of its subdirectories.
    This file is typically generated by CMake when using the `-DCMAKE_EXPORT_COMPILE_COMMANDS=ON` option.

- `--logs={CONSOLE, FILE, BOTH}`  
    Set the logging output destination.  
    Default: `BOTH`  
    **Log file location:**  
    `build\bin\logs`
